## Everyone who estimates gas through the local verifier (A, F, S)

**Do not take the pinned Helios's `eth_estimateGas` as a gas limit.** It returns the gas **used after refunds** (and a
number even for a failing call):
- On the reth fixture chain, every operator `release` sent with it failed on chain (4 of 4, status 0). With the searched
  limit, the same path lands. A release frees storage, so the limit it needs is above the gas it ends up using. Out of
  gas is inferred from Helios's code (`tx_gas_used`) and from the fix; the failing receipts' gasUsed was not recorded.
- `network/chain-authority.mjs` now searches the limit with verified `eth_call` executions at one numbered block
  (98206e643; unit test #5, failing on the old code).
- A's CLI estimates through its RPC peers, plus 20%, so it is unaffected today. Any consumer that moves its estimate to
  the verifier must use this search or a full node.

Also for F: `eth_getTransactionByHash` is now routed to the verifier (the transaction taken from its validated block
body), because the lease client's receipt check (`verifyLeaseReceipt`) needs it.
