WHAT WAS WRONG (baseline 4c059b9)
  1. A SIGTERM/SIGINT during startup made runPrivacy throw a plain Error "privacy agent stopped during startup". The CLI then
     set exit code 1, as for a genuine startup failure. Host services can print STARTED before agent.start() settles, so a
     stop right after that readiness line exited 1. Real-daemon occurrences: S c3 run3; F j2-shared (carriers d.stop code 0).
  2. The two startup catch paths cleaned up different sets of resources.
     - A failure before agent.start never closed the control transport or the paid network.
     - Neither path awaited the signal handler's own in-flight close: the agent's close() returned at once when already
       closed.
     - The signal handler's Promise.all skipped the paid close when any earlier close rejected.
  3. Root review: cleanup failures were logged and dropped.
     - A failed release looked like a clean cancellation (exit 0) or a clean stop (exit 0).
     - PrivacyAgent.close skipped the status write and router close when manager.close rejected.

THE FIX (network/privacy-agent.mjs; network/entries/privacy-agent.mjs uses the shared CLI)
  - StartupCancelled (Error; name StartupCancelled; code ENCLAVE_STARTUP_CANCELLED; same message) is the ONLY outcome treated
    as a clean stop during startup. It is thrown only after everything owned has been released.
  - runPrivacyCli(configFile), used by both entries: StartupCancelled leaves the exit code at 0, so the process exits once
    nothing it started remains. Anything else sets exit code 1. There is no process.exit and no swallowed error.
  - release() is the one path used by the signal handler and by startup's own unwinding. It attempts and awaits every
    owned close, whatever an earlier step did: host-policy gate, host proof, agent, control transport, host services,
    paid network, and the network host last. It returns (and logs) the failures. Each close is idempotent, and
    PrivacyAgent.close() now returns one shared promise, so a second caller waits for the first.
  - Startup checks for a stop after each awaited step that leaves resources (network host creation, control transport
    start, paid network), so nothing new is created once a stop has been requested. Anything an in-flight step created is
    released when that step returns.
  - Genuine failures are not hidden: startup's unwinding rethrows the ORIGINAL error (exit 1) even if a stop arrived
    meanwhile. A cancelled startup whose release failed throws an AggregateError instead: "...stopped during startup, and
    releasing what it held failed: ..." (exit 1).
  - Stops after startup: a stop whose release failed logs "stop incomplete" and sets exit code 1.
  - PrivacyAgent.close() attempts manager.close, the status write and router.close each, then rejects if any failed.
  - Unchanged: the admission, admin and host-policy gates, the order of startup, the timers, and the ownership checks. No
    contract, wallet or custody change.
