# NucBox sealed secrets

Public CPU wasi:http deployments on the Hyper-V partition backend can use the existing owner-signed secrets API, including `$NAME` and `${NAME}` references in app configuration. Secrets are released once per boot; changing secrets requires restarting the deployment. GPU and private deployments remain unsupported by this path.

The V6 catalog bundle measures the unresolved configuration and exact deployment ID. Before launching Wasmtime, the guest front creates an ephemeral X25519 key and produces a VBS report binding it to the deployment, TLS key, fresh relay challenge and runtime identity. Its `enclave-secrets-release-v1` binding domain is distinct from ordinary app attestation. The relay independently derives the expected bundle from the ledger and CID-verified catalog/configuration, authenticates the node operator and current TPM session, checks the lease twice, and permits release only to an image explicitly pinned with `secretsV1: true`.

The node forwards evidence and signed ciphertext. The guest verifies the pinned Ed25519 relay signature, decrypts, checks deployment, age, nonce and environment limits, and sends the environment to the waiting runtime over an anonymous pipe. The measured, unprivileged helper resolves configuration and inherits individual environment variables into WASI. Values are never arguments, bundle inputs, host files or log messages. The plaintext fleet fetch endpoint remains disabled for hv-node hosts. Invalid or missing releases leave the app unavailable.

The existing limits apply: at most 64 names, 4 KiB per value and 16 KiB total; no NUL/newline or reserved `ENCLAVE_` names. The guest also rejects native loader/runtime controls (`LD_`, `GLIBC_`, `GCONV_`, `MALLOC_`, `RUST_`, `WASMTIME_`, `GGML_`, `SHIELDED_`, `SSL_`, `OPENSSL_`, `LC_`, and HOME/PATH/TMPDIR/TMP/TEMP/LOCPATH/NLSPATH/LANG/LANGUAGE/TZ/TZDIR). Resolved configuration must fit 64 KiB. These restrictions prevent a WASI secret from changing the native loader or runtime before it reaches the app.

Enable only with the matching guest: manager `ENCLAVE_CONFIG_BUNDLE_V5=1` and `ENCLAVE_SECRETS_V1=1`; relay CPU policy `secretsV1: true` plus an approved image/runtime entry with `configBundleV5: true` and `secretsV1: true`. The node advertises secrets only when both its plan and manager support them. This feature does not change the platform's advertised Shield/VBS trust tier.
