# Per-app Shield inference scheduling

The first admitted profile is Qwen2.5-0.5B Q8 on a pair of 31-GiB V100 workers. Other models and optional SET/memory64/p3 inference ABIs are refused until separately qualified. This is not a 27B throughput claim.

Catalog derivation /4 adds `inference: {model, gpuMilli}` to the measured app bundle. Changing model or allocation changes AppID and measurement. The contract accepts milli-shares; the current fleet scheduler serves whole-percent shares starting at 7%, consistent with its allocation grain. Each card reserves its share of 31 GiB. The guest manager atomically reserves GPU bytes alongside CPU/RAM, retains them through teardown, and reconstructs them from the measured bundle on adoption. Inference guests have an 8192-MiB RAM floor.

`build-shielded-release.py` creates a separate pinned release containing the GGML-only runtime, public model, tokenizer, calibration and private broker. `assemble-app-image.sh` derives `/app.shield` exclusively from the validated bundle. Init fixes private routes, context512 and masking settings; no host engine environment is accepted. Prompts, masks, corrections and nonlinear operations stay in the per-app guest. App seccomp, W^X and fresh AMD attestation remain required. CPU deployments use the existing pinned CPU template unchanged.

Enable guestd with `-cpu-template`, `-shield-template` and `-shield-release` (exact manifest digest). Enable the control launcher's `isolation.shieldedInference` and explicit `isolation.shieldedPricing`. This uses existing externally managed workers on host ports9501/9502; it never enables the legacy shared-control-VM app path. Capacity requires both public masked worker probes and fresh manager profile availability. Worker probes are readiness checks, not substitutes for each inference's verification.

The relay independently confirms the deployment GPU allocation and routing manifest through two RPCs, derives the same /4 bundle, and measures only the admitted matching model profile. CPU predictions exclude model profiles. Install the release, source toolchain and matching relay changes together before admitting hosted GPU apps. Preserve old CPU releases and runtime pins during rollout. `metal/overlay-control-image.py` records bounded control changes against the previous image digest, without replacing unrelated live dependencies.

Validation: Go/reference derivation vectors; concurrent manager admission and reservation tests; scheduler model/share/release/RAM refusal tests; independent predictor profile/cache tests; actual SNP guest launch and inference, manager restart adoption with identical transport key, and reclamation. The initial scheduler hardware sample produced64 tokens at35.53tok/s on the small Qwen model. Re-run attestation and all existing app checks for the final production release. The diagnostic builder remains pinned to its historical init; never use it for private prompts.
