## What changed

The private mask bank generates sixteen independent ChaCha20 blocks in AVX-512
lanes. It retains the same twenty rounds, 256-bit OS-generated key, 64-bit
counter, output order, 64-bit field reduction and one-use issuance windows.
Every refill still computes the secret pad's weight product inside the trusted
CPU. GPU protocol, mask strength, field arithmetic and Freivalds checks are
unchanged. No pad is reused or generated by the untrusted GPU.

Bank creation checks CPU admission and compares the optimized stream with the
scalar implementation before enabling it. A mismatch refuses the bank.
`SHIELDED_NO_SIMD` overrides selection; absent, zero and invalid sampler settings
use the original scalar implementation. Requests exceeding a reserved
2^24-block issuance window are rejected before consuming an index.

Only `template/init` and `template/rt/backends/libggml-shielded.so` differ from
the previous f61fed61 release. The CPU engine remains the existing AVX2 module;
the previously rejected AVX-512 CPU engine was not used. Runtime, model,
calibration, kernel, firmware, brokers, GPU workers and affinity settings are
unchanged. The small-model profile leaves the new sampler disabled.

## Mask generation and complete refill measurements

`generation-bench.c` uses public synthetic weights and test keys, not production
secrets. It calls the actual production-built SIMD object and scalar ChaCha20
implementation, and compares every resulting field value. One warm pair is
excluded, then eight pairs alternate execution order on host CPU 15. Medians:

| K × N; batch | Sampler speedup | Complete refill wall-time reduction |
|---|---:|---:|
| 5120 × 2560; 16 | 4.26× | 21.7% |
| 5120 × 8704; 64 | 4.14× | 6.1% |
| 17408 × 2560; 32 | 4.09× | 18.5% |
| 5120 × 124160; 16 | 4.15× | 0.3% |

Complete refill includes random sampling, residue-plane conversion and the
unchanged trusted matrix product. The very wide output projection remains
matrix dominated. These are individual kernel shapes, not full-model pad
production rates or inference tokens/s. Alternative cache-slab sizes and
per-call packed weights were also explored; they did not provide a consistent
improvement and were excluded from the implementation.

## Isolated 27B comparison

Two sequential measured-image canaries, same public 17-token prompt and 128
output tokens, same Q4 model, two V100s, AVX2 CPU engine, 16 vCPUs, 50 GiB,
six compute threads and sixteen refill threads. The deployed profile ran first;
the candidate followed. Five responses per image: ordinary twice, MTP three
times. Every response independently passed AMD attestation, image/AppID,
runtime/W^X, TLS binding, second-nonce and replay checks before inference.

| Mode | Previous individual tok/s | Candidate individual tok/s | Previous aggregate | Candidate aggregate |
|---|---|---|---:|---:|
| Ordinary | 18.33, 17.71 | 18.93, 18.33 | 18.0155 | 18.6231 |
| MTP | 16.59, 16.19, 16.00 | 18.29, 16.66, 16.15 | 16.2563 | 16.9869 |

Observed aggregate gains: **3.4% ordinary and 4.5% MTP**. Aggregate rates divide
all timed tokens by all decode time, excluding prefill; each response times
127 token intervals. All ten token sequences match exactly, including across
images. No inference output mismatch or verification failure was observed.

The desktop and five production apps remained active. This is a bounded
comparison on a shared machine, not a statistically controlled throughput
promise. It does not reproduce or claim the earlier native 23.32 tok/s result.
The probe caps output at 128 tokens; this is not a sustained 256-token test.
First ordinary setup/prefill was 83.064 s before and 78.977 s after; first MTP
setup was 37.813 s before and 41.219 s after. Do not interpret only one of these
cold timings as an across-the-board startup improvement.
