## What the transaction is, and what it preserves
`EnclaveDeployments.setConfig(bytes32 id, string envelope)` writes ONLY the deployment's options envelope
(`d.configCid = envelope`). The id, owner, app, ports, shares, balance, cap, rate and lease are not touched, by
construction. The envelope is replaced whole, so each new one is the current envelope's BYTES with
`,"isolation":{"require":"snp-guest-per-app"}` spliced in before the closing brace. Every existing namespace stays
byte-for-byte; the script re-parses the result and checks it equals the old envelope plus `isolation`. After the owner
signs, `owner-payloads.mjs --verify payloads.json` re-reads each deployment and fails unless:
- the envelope is exactly the signed one;
- owner, appRef, ports, gpuMilli, cpuMilli, appPort, isPublic, active, createdAt and cap are unchanged.

Why it goes LAST: once a deployment requires isolation, every runner without it refuses the deployment. So the
signature moves the app, and it follows canary acceptance on the new release (0839ac3a).

## Checks at S5, per app, before the owner signs
1. **The staged set EQUALS the secret names the config references** (the table's row, per app). This tier delivers
   secrets ONLY by substituting `$NAME` / `${NAME}` in the config. A staged name the config does not reference would
   reach the app only as an env var on the standard runtime; here it reaches nothing (RELEASE.md, "recorded parity
   gap"). A referenced name that is not staged stays a literal `$NAME` in the app's config. The relay says only THAT
   secrets are staged. The NAMES are listed by the owner with his wallet: names only, never values.
2. **No staged name equals one of the app's own `$tokens`** (enclave-d1). Substitution would replace the app's
   variable. This matters for a69dcbba (cmd, content, factor, image, prompt, size, user); the others have none.
3. **Egress.** A guest may open only HTTPS on 443, to the origins its released config names: the literal ones above,
   plus the endpoints its secrets resolve to. Any other destination or transport is refused by the host's dialer.
   d9798e4c (an IPNS publisher) must work over HTTPS delegated routing alone (delegated-ipfs.dev, cid.contact) to serve
   here. That is confirmed at its canary, not assumed.
4. **App output.** The app's stdout/stderr reach the host (the guest's serial file). An app that logs requests,
   config or secrets would show them to the host. This is recorded in the release's "known properties".
5. **The relay lists the deployment** (`SECRETS_RELEASE_DEPLOYMENTS`, enclave-99/e3) before its guest can be a release
   guest. The production relay does not serve `release-status` yet: it answered 405 for all four.
