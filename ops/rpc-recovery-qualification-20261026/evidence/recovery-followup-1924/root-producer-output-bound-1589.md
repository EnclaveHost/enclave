# Producer r1 output bound observation (root source review)

producer/witness_producer.py:248 runs fetch under prlimit --as and --cpu only. The witness size is checked AFTER the fetch exits (lines292-297). The fetcher writes witness.json.partial and renames it. A large legitimate witness or bad fetch can therefore fill the service filesystem before post-exit cap rejection. Memory/process deadlines do not cap disk writes.

Required correction before activation: enforce an output file size limit while generating, e.g. prlimit --fsize bounded to the request cap (and document effect on all child files), plus bounded stderr/log capture. A real child test must try writing above cap, assert it is terminated/refused before disk growth exceeds the bound, no witness served, and temporary files cleaned. Do not merely test post-exit oversized files. Check existing upstream fetcher's temporary database/file behavior before applying fsize to avoid accidentally imposing an unusable limit; if per-file bound insufficient, private size-limited tmpfs/project quota or monitoring with strict headroom is needed.
