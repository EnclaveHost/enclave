## 1. The gap root found (confirmed)

The gap is in `network/privacy-agent.mjs`, at an explicit `enclaveNetwork.hostServicesPolicy`:
- The agent calls `hostPolicyCarrierGate(hostServicesPolicyConfig(hsp))` **without a snapshot**.
- `hostServicesPolicyConfig` refused any top-level authority field, so this gate **and** its carriers always read the
  policy through the block's RPC quorum: public providers.
- So moving the host-services **runner** to the verifier does **not** move the agent's own transport-admission gate.
  That gate decides whether the agent's ingress serves at all.

Found while auditing:
- **Silent mixed config.** A `chainAuthority: "verifier"` placed INSIDE the policy JSON, next to `rpcs`, was accepted
  silently: `resolveHostPolicyConfig` honours a policy-level authority. The quorum check then passed because of the
  `rpcs`, and the gate ran in verifier mode while the config read like a quorum config.
- **Ignored environment.** With an explicit block, the process environment's `ENCLAVE_CHAIN_AUTHORITY` was ignored
  silently.

The changes to `network/host-policy-gate-config.mjs`:
- **New block fields.** `hostServicesPolicy` gains optional top-level `chainAuthority` (`"quorum"` is the default) and
  `chainVerifier`, which must be a loopback URL. The loopback check reuses the platform resolver.
- **Verifier mode refuses** any of the following:
  - `rpcs`;
  - a `policy.rpcs` or `policy.minAgree`;
  - `"off"`;
  - a missing or remote verifier.
- **Policy-level authority refused.** A policy-level `chainAuthority` or `chainVerifier` is now refused in every mode,
  with the message "name the chain authority once". This closes the silent mixed form.
- **Normalized output.** A quorum block normalizes **exactly as before** (keys `policy, mirrors, rpcs, carriers`). A
  verifier block adds `chainAuthority` and `chainVerifier`.
- **Shared output.** `hostPolicyGateEnv` and `runnerPolicyShape` emit the authority, so the gate env and the runner shape
  stay ONE implementation.
- **New export `hostServicesGateAuthority(h, {env, chain})`.** It refuses when:
  - the environment's `ENCLAVE_CHAIN_AUTHORITY`/`ENCLAVE_CHAIN_VERIFIER` disagree with an explicit block;
  - the block's verifier is not the agent's own `chain.verifier` (one local verifier per host).

  It **warns** (never hides) when the agent's lease reads use the verifier but the gate keeps the quorum default.

Unchanged:
- the gate core (`host-service-gate.mjs`), `platform-host-policy*.mjs` and `policy-carriers.mjs`;
- bans, the allowlist, current-owner checks, anchor, sequence high-water, persisted refusals and grace;
- the default path with no block (it still reads the process environment, as before);
- the runner.

The Windows enrollment (`windows/node/network-enroll.mjs`) and the challenge replica use the same validator and gate, so
they accept the new fields too. Their own suites still pass (§3), but **no verifier-mode case was added for them**.

## 5. Residual production consumer paths: NOT migrated by this change (stated, not hidden)

The runner's gate does **not** cover the agent's gate, and this change does not cover the following:
1. **The DO exits' grant gate** (`network/wg-provider/main.mjs` → `createHostPolicyRuntime` from `hostServicesPolicyEnv`).
   - The exit judges the platform policy before **every** host-service grant, through **its own RPC quorum**. Its block
     has no authority field. It also reads registry rows with a two-RPC `LeaseReader`.
   - So even a host with both gates on the verifier depends on the exits' public-RPC quorum for its grants.
   - The DO servers must stay bare transports, so putting a verifier there is a design decision for root. Nothing was
     changed.
2. **The agent's app/lease reads.** `LeaseReader({...cfg.chain})` supports `chain.authority: 'verifier'`, which Windows
   enrollment writes. The live metal0 agent (release 808f691d0) uses `chain.rpc` = publicnode, drpc, mainnet.base.org.
3. **The agent's network host and provider bootstrap.** These are `createNetworkHost({rpc: cfg.chain.rpc, …})` and
   `createProviderBootstrap({chain})`: provider registry, qualification and control reads. They were **not audited for
   verifier support** in this task. Treat them as public-RPC dependent until shown otherwise.
4. **The paid network.** It follows the agent's `leaseReader`.
5. **The default gate path** (no `hostServicesPolicy`). It reads `process.env` (`ENCLAVE_CHAIN_AUTHORITY`, else the
   production RPC quorum). It now **warns** when the lease reads use the verifier.
6. **The lease relay.** It is remote: live `leaseGas.relays = https://134.209.248.172`. Its migration is underway in
   `lease-relay-source` (`LEASE-RELAY-VERIFIER-MIGRATION.md`).
7. **Others:** relay/api-relay, fleet, Windows node, site and custody host stay on the legacy quorum. Every production
   consumer must switch for the goal.
8. **Live metal0 integration does not exist yet.** The live agent has no `enclaveNetwork.hostServices`, no
   `hostServicesPolicy` and no runner. `examples/metal0-full-host-services.staged.json` is the full staged shape. Both
   gates name the same host-local verifier (`127.0.0.1:28590`), and administrative values are `<ROOT: …>` placeholders,
   never guessed.
