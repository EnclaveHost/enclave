C signed-payload execution candidate r2 — isolated, offline only

State: source prepared; NOT compiled or qualified. No accepted-domain caller,
branch selection, journal, custody selector or production launch is supplied.
No existing native binary, finalized reader, floor or admin code is changed.

Entrypoint:
  signed_payload_candidate --offline-candidate context.json witness envelope.snappy
Any other invocation explicitly refuses because the production qualified-L1 and
branch adapter is unimplemented. Successful offline evaluation is conditional
execution only and returns authority:false. It is never an authentication token.

Caller-owned context (exact keys; distinct from untrusted witness):
{
  "format":"enclave-signed-payload-candidate/v1",
  "base": { EXISTING EXACT TEN combined-r1 trusted keys },
  "parentHash":"0x...", "parentNumber":N,
  "unsafeSigner":"0x...", "envelopeKeccak":"0x..."
}
base uses chain8453, interval1, claimedBlock=N+1 and the parent output root.
The claimed output root is an expectation, not independent authority. The caller
must obtain L1 head/height, schedule/config pins, parent and signer from qualified
local capabilities. The offline CLI cannot prove that provenance; a field or
digest claiming qualification is deliberately NOT accepted as proof. Never expose
this CLI or its trusted context input through an untrusted HTTP authority endpoint.

Candidate inputs and invariants:
- One post-Isthmus V4 Snappy envelope only. Envelope digest binds exact received
  bytes; native bounded SSZ/Snappy decoding and chain-domain signer recovery bind
  its contents. Reconstruct and hash its full block before execution.
- Exactly one consecutive child of the agreed parent header/root recovered by
  the unchanged combined-r1 preimage/bootstrap machinery.
- Existing witness loader; strip every Local input; reject non-hash alternatives;
  check all hash preimages; inject only caller-owned native inputs. Reject blob
  side data because this entrypoint does not derive L2 transaction batches.
- Walk at most128 L1 headers from caller L1 head to candidate origin, checking
  each hash/height/parent. Header-by-hash alone is not canonical ancestry.
- Reuse StatefulAttributesBuilder with oracle-backed L1 receipts and parent L2
  config. Compare exact mandatory system/deposit/upgrade transaction prefix and
  forbid extra deposit transactions. Execute remaining ordinary transactions.
- Expected metadata is generated by the attribute builder, not copied from
  untrusted candidate fields. Compare the entire recomputed header, not just its
  state root, to the signed candidate; compare computed output root to expectation.
- Reuse unchanged v3 receipt/tx-root validation and complete lease-event capture.
  Coverage is for this executed candidate block only, not finalized coverage.
- Preserve config/schedule/parent/result binding via combined-r1 accept.

Bounds: context128KiB, witness128MiB, compressed envelope10MiB plus upstream
decompressed-envelope bound, result16MiB, one block, L1 ancestry128. Oversize
results/coverage refuse, never truncate. Root job must additionally apply native
CPU/address-space/wall bounds; Rust limits alone do not bound malicious execution
work or allocation amplification. Panics/missing witnesses refuse.

Conservative r2 scope: reject every over-drift origin, including protocol cases
where a deposit-only block could legitimately exceed drift. No branch selection,
maximum-age authority, confirmation counting or origin-selection policy is claimed.
Those are release gates, not hidden defaults. V4/signing-key/fork support must be
checked against real current Base data before any broader use.

Output: enclave-signed-payload-candidate/v1, authority:false, explicit conditional
meaning; exact L1 head, parent, envelope digest/signer, schedule/config hashes,
full computed header/hash/outputRoot and complete lease coverage. Never consumed
by finalized reader v2/v3 or advertised as safe/finalized. No journal is written.

Tests supplied: actual prefix acceptance and missing/reordered/extra-deposit
mutants; full-header root/gas mutations; exact parent/height mutation; missing
context refusal; inherited unchanged combined/v3 tests. These are meaningful
local invariant fixtures, NOT a successful signed-block execution fixture.
A real positive context+witness+signed-envelope triple is still required. It must
come from the coordinated witness backend or an independently validated capture;
do not fabricate L1 provenance to make this gate pass.

Required next fixtures: real positive contiguous block with authenticated L1
origin/config; wrong signer/domain/envelope/parent; missing/changed preimage/code;
omitted/extra deposits; malformed L1 origin/receipt ancestry; schedule/upgrade
boundary; changed state/tx/receipt/header root; oversized output; missing historical
state; runtime abort. Then branch/canonicality/complete-history/full-feature tests
from the architecture report before integrating any authority adapter.

Build ownership: root coordinates the resource window. jobs/build-test.sh is a
root-run recipe under the existing memory guard and unshare -Urnm. It reuses the
single existing lease-v3 native cache under its exclusive lock. It bind-mounts
small source/manifest/lock overlays in a private mount namespace, preserving
physical finalized source and binary. No dependency/cache copies or network.
The new Cargo.lock changes only the zk-utils direct dependency edge to an existing
workspace package; --frozen --offline must validate that assumption. A frozen-lock
error must be reported, never worked around by downloading/updating dependencies.
