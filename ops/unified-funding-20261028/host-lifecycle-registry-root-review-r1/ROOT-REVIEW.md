## What this does not prove

The contract can record Offline without depending on an external oracle/payout/ownership call after local authentication, even at low/zero reimbursement. It cannot guarantee chain inclusion during arbitrary outages or prices. Protected reserve >= payer per-transition cap is an accounting constraint, NOT proof of enough gas for an actual offline transaction: the intentionally1-wei test demonstrates that budget admission itself lacks a measured affordability floor. Before production Online admission, a real qualification/sponsorship policy must verify a conservative execution+L1 envelope and available independently funded submitter. L1 reimbursement is not implemented; its signed allowance is inert. Never weaken Offline availability to repair Online affordability.

Real fresh attestation/capacity test execution and independent receipt issuance, online paid-work sponsor selection/verified-absence Stripe fallback with liabilities, durable report sender/reconciliation, capacity projection/UI/scheduling and positive Base authority are not implemented by these tests. The current schema3 adapter still refers to a separate HostOwnership contract; the new explicit profile must bind registry and ownership roles to this SAME new canonical registry with exact code and one authenticated block. The next source-only integration task preserves old profiles/defaults and every recursive code/immutable/owner gate. No automatic activation, reinterpretation of old gas grants or production restart is authorized by unit-test success.

This is progress within the highest-priority feature of full censorship-resistant decentralization. Full independent deployment/cold recovery/storage failure/refusal behavior remains unproven. Reviewed originals/diffs/tests/compiler artifact are retained in the peer registry stage and packaged in its repository; this root package records independently checked evidence and limitations, not a production installer.
