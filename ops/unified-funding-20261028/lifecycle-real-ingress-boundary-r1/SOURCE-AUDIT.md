# Actual consumer composition: reuse points and remaining boundaries

Read-only source audit of the pinned lifecycle checkout, not installed-byte or live-service qualification. SOURCE-AUDIT-PINS.json binds the inspected files. No production changes or hardware experiment.

| Boundary | Existing concrete path | Requirement still open |
| --- | --- | --- |
| Direct guest connection | network/privacy-agent.mjs constructs GuestdIngress; network/guestd-ingress.mjs selects a unique running deployment over authenticated loopback manager control, checks app/runtime/measurement identity and uses the verified splice. | Connect the independently verified lifecycle permission and owner-lifetime revocation to the actual construction. This direct route does not require the supervisor CVM or public app DNS to select a guest. It was inspected, not exercised by the TLS fixture. |
| App network ingress | createAppIngress checks authorize at accept and ClientHello, restricts names to the app, and has revoke/close. createAppBroker binds one deployment to a private Unix socket or authenticated loopback connection. | The new test exercises these actual modules through real TLS. Production must register their actual resources with the owned permit gate; a synthetic allow acknowledgment is insufficient. |
| Network worker lifetime | wg-circuit-runtime passes admissions/deadlines to worker; windows-circuit-worker enforces expiry and stdin closure. | Verify actual lifecycle grant/context/deadline propagation in the installed host configuration and process-loss cases. Offchain permit renewal is distinct from prohibited periodic onchain renewal. |
| Compute after supervisor loss | guestd server.go leaseExpired intentionally returns no expired guests when no supervisor heartbeat has arrived or the supervisor is silent; server_test.go retains compatibility tests for that behavior. | Existing legacy heartbeat is NOT an independent lifecycle permit deadman. Implement an explicit per-app migrated lifecycle boundary that enforces authenticated bounded grants despite parent death, without changing the legacy fallback for unmigrated tenants. Preserve launcher resources/pad guard/administrator controls and production floors. |
| Manager control API | windows/node/isolation-client.mjs and guestd/control-client.mjs provide existing authenticated manager operations. | Add or reuse a qualified lifecycle-specific deadline/revocation API; do not claim a Node callback proves detached-process enforcement. |
| Storage and secrets | The staged runtime requires storage/secrets boundary acknowledgments, but this fixture uses TEST callbacks for them. | Wire actual independently authorized data/custody access and closure. No production secret release or persistent storage authority is qualified by a TLS test. |

A narrow search in network/ and windows/node/ found only the class/factory definitions of DeploymentPermitGate/createIsolationLifecycleRuntime/createPermitCollector, not a production constructor call. That is evidence of a missing connection in these inspected consumers, not a repository-wide absence proof. Current real privacy-agent guest ingress is an available reuse path; do not replace it with an Enclave-operated replica or remove its identity/attestation checks.

Required next operational proof includes manager/parent process loss, closed ingress and storage writers, cancelled secret release, authenticated independent Offline submission, safe staged restart and cold recovery under Enclave refusal. Source and local TLS success are not those demonstrations.
