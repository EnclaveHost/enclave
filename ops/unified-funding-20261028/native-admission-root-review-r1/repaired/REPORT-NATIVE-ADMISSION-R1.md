# Native admission envelope R1: source-only report

Status: **SOURCE ONLY. Nothing was built or run.** No Windows admission happened, and nothing native is qualified. Every invocation of the current source refuses before creating any child.

## Delivered (candidate/)
- `admission-envelope.c` is new. It is no-CRT and imports only kernel32 and `BCryptHash`. It runs one phase per invocation (`limits` or `death`), plus an internal `observe` mode for the independent observer.
- `owned-job.c` has a minimal R1 interface change. It no longer creates, self-assigns or terminates a Job. At entry it must be the only process (active=1, total=1) of the exact preconfigured Job T, otherwise it exits 96. Its secondary pressure floor is now 18432 MiB. It stops only its own direct child. The envelope owns T.
- `job-probe.c`, `no-crt.c` and `exlock-test.cjs` are unchanged. The probe's evidence semantics are kept: T has the same flags, caps and 3-process baseline.
- `build-request.json` (review-only), `run-contract.json`, `admission-envelope-cases.json` (offline, not run) and `RELEASE-CLOSURE-NATIVE-ADMISSION-R1.json`.

## Mechanism
1. **Bootstrap before entry.** The envelope never assigns itself to a Job. Its first gate checks that its immediate Job E has exact flags `0x261C` (no breakaway), 384 MiB job commit, 7 processes, affinity 1, 30 s CPU, and that the envelope is E's only process ever. Then it checks the inherited creator process handle against the exact PID and creation time, that the creator is alive, and that it started earlier. If any check fails it returns `BootstrapUnqualified` / `CreatorIdentityRefused` before any child. The creator's fixed steps are in `run-contract.json#creatorContract`.
2. **Enforced O and E.** Test T (256), observer O (64) and the envelope's own early/steady remainder (64) are all nested under E's hard 384 MiB commit cap. So `256 + O + E = 384` is enforced by job accounting, not estimated. Kernel pool, page tables and shared image pages are not job-charged. That residual is stated, not hidden.
3. **Capacity.** The rule is `availPhys ≥ max(18432, liveFloor) + P + 384` and `availCommit ≥ commitP + 384`. Both are checked on fresh `GlobalMemoryStatusEx` readings: once before any child and again immediately before the launcher resumes. Unknown, stale, implausible (wrapped-negative) or overlap-unbounded inputs refuse. The terms come only from `capacity_hold()`, which returns `CapacityInterfaceAbsent` because that interface does not exist. Inputs from argv, files, JSON, Booleans or historical observations are never accepted. Queue length is not a term, and nothing requires draining.
4. **Limits phase.** The envelope creates unnamed Job T, configures it, and attaches a completion port. It creates the launcher suspended, passing exactly the three std handles through `HANDLE_LIST`, with the fixed encoded PowerShell `& .\job-probe.exe`. It assigns the launcher to T and verifies membership and that T's process counts are 1/1. It re-admits, then resumes. While waiting it watches the launcher and the creator, sampling pressure every 50 ms (best effort). It has a 35 s deadline. At the end it calls `TerminateJobObject(T)` and reports drained=false unless T is observed empty.
5. **Death phase.** The tree is the same, with the probe in `child` mode. Ready means three `NEW_PROCESS` messages from T's own port: the first must be the created launcher's PID, and the other PIDs are opened only while they are proven members of T. T's counts must then be 3/3. Any exit message before that refuses. The observer is created suspended and assigned to Job O: 64 MiB, 1 process, 5 s CPU, and no kill-on-close, so the owner's death does not kill it. The envelope verifies the observer is not in T. The observer inherits only stdout, the envelope's process handle (the wrapper and sole T owner) and the three tree handles. It never receives T. It checks every identity, then terminates only the exact wrapper handle with a nonce-derived code. It then waits for the exact descendants and compares their exit FILETIMEs with the action time. It runs positive controls and reports one of five outcomes; on timeout the outcome is `unknown`. `ownerDeathQualified` is always false. Nothing retries, follows on or cleans up.

## Remaining source interfaces
- **Creator** (`run-contract.json#creatorContract`): a separately reviewed, already constrained program. It configures E before CreateProcess and resume, keeps E's handle to itself, and owns a 60 s wall deadline plus finite pipe budgets. The envelope cannot verify from inside that E's handle is held only by the creator, or that the creator's deadline is real. Those stay creator-review obligations. The creator's own footprint is outside this envelope. That is where the recursion stops, explicitly; no self-watchdog chain and no SSH timeout is claimed to close it.
- **Capacity hold** (`run-contract.json#capacityHoldInterface`): a local test-capacity hold at the actual shared allocation boundary, honoured by every manager and direct admission path. It must carry incarnation/sequence, the validated live floor, P and commit upper bounds, a held budget ≥ 384 MiB and a finite expiry. `currentP` stays null.

## Not claimed
- The old 17408 MiB launcher (sha `94a8483e…`) is not sufficient and is no longer the R1 launcher.
- The source, these cases and any future build are not native evidence.
- Sampling the pressure monitor cannot stop an allocation that lands between samples.
- Possible conhost processes inside T would break the ready and probe baselines. That case refuses; it does not pass. A reviewer must check the subsystem of the historical PE files.
- `BCryptHash`/`BCRYPT_SHA256_ALG_HANDLE` header availability, and whether the pinned toolchain avoids `__chkstk`/`memcpy`, are unverified until review.
