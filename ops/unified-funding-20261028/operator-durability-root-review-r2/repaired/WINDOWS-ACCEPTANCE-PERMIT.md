# Windows acceptance procedures — permit r1 (AUTHORED, NOT RUN)

Nothing below has been executed. Each item needs a separately authorized run on a real Windows Hyper-V host (T0-hv, host not excluded). Results from the Linux tests in `test/windows-permit/` do **not** satisfy any of them.

| # | What must be shown on real Windows | Procedure (summary) | Pass condition |
|---|---|---|---|
| W0 | Staged installation | Review and run `control/windows/vbslike/guard/install-guard.ps1` on a test host only. Record the printed SDDL strings into both pinned configs. | Directory and journals are on fixed NTFS with no reparse points. Inheritance is off. A rerun refuses because the journals and keys exist. |
| W1 | `UV_FS_O_EXLOCK` exclusion is real | From two separate `node.exe` processes, call `openOwnedLog(journal, {exclusion: WINDOWS_EXCLUSION})`. Then kill the first one with `taskkill /F`. | The second process gets `JOURNAL_OWNED` while the first is alive. After the kill, the second opens without any manual step. Rename and delete of the held file fail from Explorer and PowerShell. |
| W2 | Flush and power-loss ambiguity | Loop appends with `FlushFileBuffers` (fsync) and cut power, or use a VM hard reset, mid-loop. Repeat at least 20 times. | Every reopen is one of: a valid chain, or a torn tail that refuses writes until explicitly quarantined. No acknowledged record is ever missing. Nothing is silently truncated. |
| W3 | Guard as a boot-start SYSTEM process | Start the guard. Attach the manager. Stage one protected V1 instance. | Guard status is `ready` with `exclusion=windows-exlock`. Manager `/health` `permitEnforcement.reasons` contains only the authority-reader reason until a production reader exists. |
| W4 | Manager death removes exact compute | With a protected instance serving and one legacy VM running, kill `node.exe` (manager) with `taskkill /F`. | The guard removes exactly the protected VM by GUID with Notes-identity match, confirmed by `Get-VM`. The legacy VM is untouched. The guard journal shows `removed` with `confirmed.by=survey`. |
| W5 | Guard death and restart | (a) Kill the guard while an instance is serving. (b) Restart the guard over the same journal. | (a) The manager closes splices at once, reports capability false, and removes the VM itself. (b) The restarted guard marks every non-terminal registration `removing` and removes it. It continues no lifetime. |
| W6 | Reboot | With a protected VM serving, hard-reset the host. Hyper-V automatic start action set to *start*. | After boot the guard (boot id changed) removes the VM before the manager can serve it. The manager's `recoverAtStartup` also removes it. Neither serves it. |
| W7 | Composite router path | Upgrade the legacy-role (8091) manager to this source with `ENCLAVE_PERMIT_CONFIG`. Stage, permit and splice through 8097/8098. | The response MAC verifies at the client through the router. The router latch is pending during the stage and observed after it. Expiry closes the router-side splice. |
| W8 | Hung WMI removal | Make `CMD.removeById` hang, for example by holding a VM lock with a long `Get-VM` pipeline or suspending the vmms worker on a lab host. | Splices close immediately. The record stays `remove-failed` or `removing`, never deleted. Removal is retried and confirmed only by survey. |
| W9 | Process identity | Attach to the guard with a correct key but the wrong `created` value for the PID. Then restart the manager under the same PID if PID reuse can be forced. | The guard refuses the attach. A reused PID with a different `CreationDate` ends the session (and removes the instances). |
| W10 | Clock and suspend | Change the wall clock forward or back by 10 s while serving. Separately, sleep and resume the host. | The gate closes on discontinuity, access is withdrawn and the VM is removed. After resume, wall-deadline expiry removes the VM even if the monotonic counter paused. |

Out of scope for every item: protection against a hostile host administrator (who can stop either process), attestation of the manager, live Base qualification, and secret, desktop or GPU protected instances (refused in r1).
