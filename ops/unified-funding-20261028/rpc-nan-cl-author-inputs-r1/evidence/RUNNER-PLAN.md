## Safe ownership adaptation on the isolated derivative

Use a freshly created root:root0700 outer directory /srv/enclave-l1-nan-<nonce>, with the ext4 mount at its volume child. Original UID995/GID986 files are inaccessible to Nan enclave-checker while parent0700. Do not chmod the mounted filesystem root or change ownership elsewhere. Mount only private COW; parent original remains read-only locked. No clients started; independent guardian owns attachment lifetime. Require exact mounted device and no other namespace mounts/holders/users.

Preflight the entire cl and tmp-cl subtrees before any ownership change: bounded depth32,20000 entries,3MiB metadata ledger,60second deadline and continuous disk/memory guard. These are explicit initial bounds, not assumed sufficient; overflow fails and retains derivative without expanding automatically. Traverse with directory FDs/O_NOFOLLOW and stat/open identity checks, never follow symlinks or cross st_dev. Permit directories and singly linked regular files only; require each owner exactly995:986, reject special files,symlinks,hardlinked regular files,setuid/setgid,POSIX ACLs,security.capability and other unexpected ownership-affecting metadata. Record relative path,type,dev,inode,uid,gid,mode,size,mtime_ns,nlink and xattr names/values or bounded digests. Check cl/beacon/chain_db exists. Data/tmp and all sibling subtrees are out of scope and never traversed for mutation.

If every entry passes, remount the owned COW RW,nosuid,nodev,noexec and revalidate every inode before change. Root-only access and no concurrent writers make the two-pass inventory meaningful; nonetheless recheck dirfd/path identity immediately before each operation. Open each verified entry by anchored FD, fchown exactly that descriptor to the fresh dedicated CL UID/GID, verify uid/gid plus unchanged mode,size,mtime,nlink,type and xattrs. Do not use chown -R or path-following libraries. fchown changes ctime and filesystem metadata/journal; it does not write file payloads. It can clear privilege metadata, which is why such files are rejected preflight. This is not a full byte-for-byte database hash proof; original header+identity and read-only backing guarantee original preservation, while the constrained syscall path avoids file-content writes in derivative. If a partial failure occurs, do not repair in place or start CL; keep outer parent0700 and mark derivative incomplete for root review.

On success fsync changed files/directories as supported and the filesystem before an independent ownership/metadata rewalk; record exact changed count and manifest hash. Set outer directory root:newCLgroup0710 only after complete verification. Existing Nan users/groups retain no traverse. Unit runs dedicated non-login user,new group,JWT supplemental group only,ProtectSystem=strict,ProtectHome,PrivateTmp,NoNewPrivileges and RW exactly volume/cl,volume/tmp-cl. Make volume/data and volume/tmp inaccessible in the unit; no old-owner account reuse. Fresh JWT root:dedicatedJWT0640 outside COW. Store ledger/receipt root0700 outside mutable subtree. Close mutation descriptors before launching client.

This does not require idmapped mount qualification. An idmapped alternative is deferred because it adds mount/user-namespace/tool compatibility work; bounded ownership changes on an immutable-backed derivative are easier to review here. This is not authorization to change original DB ownership.
