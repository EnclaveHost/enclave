## Findings that matter before a derivative write

1. **Holder visibility prevents the ordinary-user path from completing.** `scan_holders` (922) examines every PID and `holders` (1159) refuses any unreadable descriptor directory, even for unrelated privileged processes. This is conservative but is not a workable completeness proof from an unprivileged process. Smallest resolution: a separately reviewed, bounded privileged read-only holder helper, called within the same locked operation, returning only matching device/inode holders and completeness. It must handle PID disappearance versus permission errors explicitly. If such privilege is unavailable, the documented alternative must rely on verified native QEMU locking plus the known access/ownership model; it must not relabel incomplete `/proc` visibility as complete. Do not add an allow-all-unreadable switch. Root decides the applicable trust boundary.

2. **The custom OFD protocol needs direct native confirmation.** `hold_qemu_locks` (901) uses hardcoded 100–299 bytes and read locks on 201/203. Python's lock operations succeeding only proves those bytes were locked. It does not establish their meaning to the pinned QEMU build. No matching QEMU raw-posix source was found in the local paths inspected. Qualify: writer already open before acquisition must refuse; after acquisition, a new qemu-nbd writer and resize operation must refuse without changing the fixture; read-only access has an explicitly recorded expected result; acquisition/release must preserve fixture hash; a second OFD owner must observe contention. Include QEMU WRITE_UNCHANGED and metadata permissions when determining which bytes must be protected—do not assume WRITE/RESIZE alone covers every modifying native path. A stopped-VM check and advisory workflow lock complement this protocol, not replace it. Raw noncooperating writers remain outside advisory lock protection; do not promise protection from arbitrary privileged writes.

3. **Failure cleanup can leave an untracked exporter or mount.** `export_start` (1004) can observe a mount with the wrong size, time out, call `export_force_cleanup(h, None)`, and throw before `Writer.export` registers the handle. That failure path has no fusermount cleanup. `export_force_cleanup` (1050) stops waiting when the leader exits, without checking that its qemu-nbd child/session and FUSE mount are gone. Registration/ownership must start as soon as the child exists, and cleanup must verify both descendants and mount after a bounded TERM/KILL sequence. Retain start-time ownership and never signal a reused PID. Root should test a leader that exits while its child remains, failure after mounting, and cancellation during mutation. These tests use only owned synthetic resources.

4. **Exporter log bounds are checked too late.** `export_start` redirects stderr straight to a file; `export_stop` checks its size only after normal exit. A failing exporter can consume disk while the parent is hashing or blocked elsewhere. Use an actually bounded drain or a separately enforced file-size limit, record overflow as failure, and perform the same check on failure cleanup. The command-output collector's bound does not cover this file. Space checks before/after copy do not continuously enforce the storage floor during a later export.

5. **Rollback and preservation claims exceed collected metadata.** `inventory` (569) records enablement symlink inode/mode/uid/gid/size/target/link count but no timestamps or xattr values. `ROLLBACK.json` therefore cannot restore all metadata promised by the procedure. `parse_stat` (489) hashes rendered xattr text, not necessarily complete raw values; a missing/unparsed xattr section can resemble no attributes. For this operation, the smallest route is to verify target fragments/links have no ACL/xattrs using explicit native inventory, preserve all timestamps and reject unsupported attributes. If attributes exist, capture exact values privately rather than claiming a textual hash is a restorable copy. The native fixture's regular-file metadata and exact ln/unlink result support those fields, not general xattr preservation.

6. **The unrelated-unit check misses content changes of equal size.** `inventory` hashes only the eight `/etc` fragments and selected drop-ins. `semantic_delta` (652) compares inode, owner/mode, size and target for other entries. A same-size change to another regular unit would pass. Hash all regular unit-tree files within the reviewed scope without logging contents, or narrowly state a weaker guarantee and add the independent content comparison needed before publication. Directory-size changes caused by removing entries are legitimate; their content identity should come from the complete entry set.

7. **The read-only-to-writable gap has incomplete revalidation.** The writer closes its read-only exporter, then opens a writable exporter and rechecks only the eight fragment stat records (1379 onward). Enablement targets/inodes and ancestor/archive state are not rechecked before destructive operations. Keep the derivative inaccessible to competing users and native-locked throughout the critical interval, and revalidate the complete planned mutation inputs after acquiring the writable export. The `unlink`/`rm` operations should verify they still address the recorded inode/target immediately before removal. A drifted link must fail before removal. Source/backup native locks do not reserve the derivative while no exporter has it open.
