## Minimal missing interfaces, in order

1. **Finish single-client startup qualification, then bounded pairing.** EL recovery and Nan startup success must include clean independent teardown and measured full startup memory; current noOOM partial results do not establish steady-state pairing. Pairing requires simultaneous reservations on Control, Nan and Warden (both exporters/tunnels/helpers), not the sum of separately admitted trials. Keep existing caps/reserves until root reviews measured changes. P2P availability also remains necessary: EL binds30313 plus discovery30314; CL9310/quic9311. RPC tunnels do not replace P2P peers.

2. **One shared private JWT lifecycle.** Both trial client-main.py files currently independently generate secrets.token_hex(32), fsync and set root:localJWTgroup0640. Thus two successful standalone clients still cannot pair. Add a narrowly scoped root pairing provisioner that generates ONE new secret once, installs identical bytes through authenticated encrypted transport into each new pair-owned credential path, and returns only provenance/equality/permission status. Control group enclavel1jwt GID50002; Nan enclavenanjwt GID50012; use each local verified group, never copy numeric ownership between hosts. Current unprivileged client units already use SupplementaryGroups. Keep parent authority, no symlink replacement, exclusive creation, durable writes, no secret values in CLI/env/evidence or source pins. Reuse node-payload-v4/install.sh's persistent /etc/enclave-rpc/jwt.hex convention, but not its old account assumptions. Define coordinated rotation/restart and rollback ownership; do not reuse or expose a consumed trial key. Qualification must show actual Engine authentication and wrong-key rejection, not only an open TCP port.

3. **Two fixed encrypted loopback mappings.** Reuse existing run-body.py SSH policy (BatchMode, StrictHostKeyChecking, known-host identity, Control ProxyJump/minipc identity, ServerAlive5/count2, ExitOnForwardFailure) in dedicated pair-owned services. Minimal topology, if no direct authenticated Control↔Nan path exists: Warden has one pinned Control SSH session with local Engine forward and remote beacon forward, and one pinned Nan SSH session with remote Engine forward and local beacon forward. Explicit127.0.0.1 binds at every TCP hop; fixed destinations only. Warden intermediate ports are allocation inputs to inspect/admit, never guest endpoint configuration. Neither direct cross-host reachability nor port vacancy/sshd forwarding policy is proven here. This reuses SSH, not a new proxy framework. Assign CPU/memory/tasks/time/start limits to every session under combined admission; transport loss must revoke pairing/readiness and stop dependent workload according to reviewed ownership. Existing NBD-only Unix forwards are not Engine/beacon forwarding. Shared JWT authenticates Engine, SSH supplies channel confidentiality. Base on a third host would require its own two loopback data mappings and fresh placement admission; no Base placement is selected by this map.
