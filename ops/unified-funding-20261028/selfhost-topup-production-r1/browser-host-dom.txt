    - heading "What can be listed" [level=2]
    - list:
      - listitem: "A confidential server: a CPU with a hardware TEE, optionally a GPU in confidential-computing mode. Tenants' memory is encrypted against your operating system and their TLS terminates inside the VM. It is listed with a jade tee cpu badge and sells the full service; the rest of this page describes it."
      - listitem: "An Enclave Shield host: hardware-enforced CPU isolation keeps the host OS out, even without a confidential-computing processor. It must pass the same acceptance tests before taking tenant work."
      - listitem: "Any other GPU, including a card beside a confidential processor: it serves through Shield's masked offload, whatever the CPU or operating system. A card in a supported confidential-computing mode runs inside the boundary instead. Admission reads proof of the card's own mode, and a card is neither advertised nor routed until Shield's checks pass."
    - paragraph:
      - text: Eligibility comes from proof checked at attach, never from what a machine says about itself or which operating system it runs. A machine takes general tenant work only after marketplace admission, which for a new confidential box means a published allowlist of measurements. Owner-authorized hosting is listed separately when it has active deployments and does not grant admission.
      - link "What each level guarantees, exactly →":

    - heading "What a confidential server needs" [level=2]
    - list:
      - listitem: A CPU with a hardware TEE and virtualisation available to the OS. Confidential VMs are what make the guarantee real; a box without one cannot sell this tier.
      - listitem: Linux with KVM and a few gigabytes of RAM to give the guest. The build runs unprivileged; only the one-time device permission needs root.
      - listitem: A little gas. Your box registers itself and claims work with its own key, which costs a few cents of Base ETH. The CLI funds it from your wallet in one transfer.
      - listitem: No public IP. The enclave dials out and holds the connection, so a home machine behind carrier NAT works.
      - listitem: A GPU is optional. CPU-only boxes serve CPU work; a GPU in confidential-computing mode sells GPU shares too.
    - heading "Setting it up" [level=2]
    - paragraph: Everything is one command line tool. Each step below is also a plain script in the repository if you would rather drive it yourself.
    - generic: terminal
    - button "✓ copied"
    - code: "curl -fsSL https://get.enclave.host | sh enclave host init # mint this box's key, write its config enclave host build # build the measured guest image enclave host run # boot it, ctrl-c to stop enclave host check # is it answering, is the quote real hardware enclave host install # run it under systemd instead, enabled at boot"
    - paragraph:
      - code: enclave host build
      - text: assembles the guest from a tagged release, and folds the kernel, the initramfs and the boot arguments into the launch measurement.
    - generic: Reproducible
    - paragraph: That measurement is computed from the tagged release and the kernel your box boots the guest with, so anyone with the same kernel can rebuild it and check the number your box reports.
    - heading "Getting paid" [level=2]
    - paragraph: Once the box has gas, it registers itself and claims funded deployments from the queue. The ledger escrows the runner share of each payment, credits your operator key for the time you actually hold the lease, and sweeps the balance to the wallet you named once it clears the payout threshold.
    - generic: terminal
    - button "✓ copied"
    - code: "enclave host fund --eth 0.002 # gas the box, one signed transfer enclave host status # gas left, serving or not, earnings accrued"
    - paragraph: You set your own price. A box can name what it charges per hour for a full node and, if it has one, a full card. It then refuses work paying less than that, and the number is published alongside its capacity so buyers can see it.
    - generic: terminal
    - button "✓ copied" [active]
    - code: "enclave host init --price-cpu 2.50 # USD per hour for a full node"
    - heading "What tenants get, and what you can see" [level=2]
    - paragraph: Apps that land on a confidential server each run in their own confidential VM, and the memory of each VM is encrypted by the processor against your operating system and every process on it, root included. You host the work without being able to read it. Their TLS terminates inside the enclave too, so traffic passes through your machine as ciphertext.
    - paragraph: "That cuts both ways, and it is the point: buyers do not have to trust you, so they do not have to know who you are. What they check is the attestation your box produces, against the measurement of a published release."
    - paragraph:
      - text: "One limit is told to buyers, not hidden: the processor defends memory against software, not against physical attacks with lab equipment, and you have physical access to your own machine. Buyers who need to rule that out see who runs each host and choose accordingly."
