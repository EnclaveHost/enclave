# Targeted stopped-app release — source preparation only

Prepare a three-file patch on the captured installed Windows baseline so an authenticated local operator request can release exactly one inactive, affirmatively retired app through the existing signer queue and release journal. Current installed APIs do not provide this operation. Caps changes, stopping an app locally, DELETE on a deployment route and restart routes are not substitutes.

Only the coordinator may admit the author, tests, build, production activation or financial actions. This package performs none of those. The author runner and terminal collector are unchanged from the reviewed repair-r2 package. Account must be independently checked by coordinator and runner; an old Max result is not current admission. PREPARED.json must be bound by root-author-approval.json. One invocation only; no automatic retries.

The exact archived control tree is both seed/ and candidate/. Agent/host/chain/generated lease bundle hashes match independent installed captures. This is disk-source provenance, not loaded-code proof, and does not prove all archived modules are installed now. No product code was pre-edited. Tools are limited to Read/Grep/Write/Edit; this is not an OS security sandbox. Manual mutation/scope review remains necessary. Terminal collection freezes once only after the actual admitted unit and author process tree are gone.

Actual-signing checks are required in addition to queue-time checks. The generated bundle has asynchronous RPC and relay discovery before calling account.signAuthorization and account.signTypedData; onSigned is too late. Keep any account wrapper local to the exact queue operation and delegate only to the same configured account.

Pending DNS release is a production concern owned by the coordinator. Previously completed refund/transfer transactions must not be replayed. KVM was last reported active and is refused by this route until fresh evidence says otherwise. All task examples are non-secret and must not be treated as live evidence.

An eventual agent-only restart still interrupts its network listeners and proxy streams. Separate manager/guest preservation is conditional on actual ancestry/job ownership and startup reconciliation. Existing source has no qualified graceful send-queue drain for replacement. These are explicit deployment blockers, not authorization to broaden this route patch.
