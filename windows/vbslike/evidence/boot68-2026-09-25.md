## Legacy backend impact (recorded separately from the custom type-1 path)

The legacy engine cannot run under Secure Boot:
- `ee-host` fails with `LoadEnclaveImageW failed: 577` (`ERROR_INVALID_IMAGE_HASH`), 77 times since boot.
- The node takes no new app, and its local API on 9600 does not answer.
- The old VBS-enclave apps are therefore down.

Per Steven's direction this is **not** a recovery target (`../DIRECTION.md`).

Whether the custom type-1 path works under Secure Boot is a separate, open question. Its first observable is whether
Hyper-V loads our unsigned IGVM at all. It is tested by a bounded canary, not assumed from the enclave's signing
rules.

## Custom type-1 path under Secure Boot: bounded canary 054323 (05:43:23-05:44:37Z)

Configuration:
- type 1, CONTROL firmware `32d464cc` (unsigned OpenHCL IGVM), production medium `ca245eae`, VBS opt-out;
- AllowFirmwareLoadFromFile applied for the run and restored to absent (verified);
- `uefi-dev-boot.ps1` with `-LegacyBackendRetired`: the empty legacy baseline is recorded, not refused;
- no memory read.

**First observable, recorded on its own:**

    05:43:59 FIRST OBSERVABLE: Start-VM ACCEPTED the partition (state now Running)

**Then the guest:**
- `MON ready` came 325 ms into the guest's boot.
- `MON boundary ... host_excluded=no hv_isolation=vbs paravisor=no`.
- wmiserve reported `isolationType 1`.
- hello-world served its pinned 13 bytes (`03ba204e…`).
- Worker 18615: "VM guest state encryption key not released".
- **Run and cleanup:** RUN OK; the setting and the hv_sock key were verified restored; node pid 20692 was unchanged.

**What this establishes about Windows' requirement for loading the isolation firmware (this build, boot 68):**
- With Secure Boot ON and HVCI running, Hyper-V loads our unsigned IGVM and starts the partition while
  AllowFirmwareLoadFromFile is set.
- The old VBS-enclave signing rule (error 577 for the test-signed enclave DLL) does NOT apply to this path.
- **Inverse control, canary 054616 (`-WithoutFirmwarePolicy`, same definition, setting NOT applied): REFUSED.**

      05:46:50 FIRST OBSERVABLE: Start-VM REFUSED: ... Loading custom IGVM files is not allowed without a registry opt-in.
               ... failed to start worker process: The request is not supported. (0x80070032).
               ... failed to load custom IGVM file because AllowFirmwareLoadFromFile registry key is not set.
      Worker-Admin 5142: failed to load custom IGVM file because AllowFirmwareLoadFromFile registry key is not set.

  So on this build the registry opt-in is what gates loading our firmware, with Secure Boot on or off. Secure Boot
  itself did not refuse it. The inverse run left no VM, the setting stayed absent, and the hv_sock key was removed.
- AllowFirmwareLoadFromFile is a host-wide developer setting that Microsoft describes as enabling unsigned images.
  Relying on it in production is a separate decision.
- The firmware's trustworthiness comes from its measurement in the report, not from Windows' load policy.

## The legacy node process exited on its own during this window (recorded, not repaired)

  `Error: port 9596 never opened`.

- Cause: the legacy engine cannot load under Secure Boot. It is not this lane's runs.
- Per DIRECTION.md the node is NOT restarted onto the legacy path. It runs again once enclave-5d's engine-free
  startup for the custom backend exists. No state was deleted.

## What this establishes, and what it does not

- VERIFIED: for boot 68, a remote verifier can establish four things:
  - a genuine AMD firmware TPM, by the EK chain to the pinned root;
  - a quoting key resident in that TPM, by real credential activation;
  - a fresh quote over its own nonce;
  - a measured boot that replays to the quoted PCRs, with Secure Boot on, test signing off and debug off.
- The boot-state rejection conditions of the contract are absent on this boot. That is not a pass of anything else.
- NOT established: that the host cannot read guest memory (E3 parked); who signs the paravisor's VM report (IDKS
  remains a hypothesis); any binding of a guest key or app identity to a report; PCR 0 firmware pinning.

`host_excluded` stays `no`.
